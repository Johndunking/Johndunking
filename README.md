**What I build**

**SPEDstack** — an educational workflow platform for instructional planning, scheduling and
administrative coordination. Python, FastAPI, SQLAlchemy, PostgreSQL/Cloud SQL, Docker,
deployed to Google Cloud Run with IAM-authenticated database access. Sole author of roughly
116,000 lines across 238 commits, with 5,930 passing automated tests.

**ReadingAvatar** — a K–3 literacy application in which a child's reading aloud drives the
gameplay. On-device speech recognition and a mastery estimator that weights evidence by how it
was gathered. Swift/iOS, migrated to Unity/C#. ~1,100 automated tests.

**VisualAvatar** — individualized visual supports for iPad: visual cues, first–then boards,
choice boards, task sequences. Architected to run fully offline with no student accounts and
no data transmission, enforced by an automated architecture check that fails the build if
networking, analytics or third-party dependencies reach shipping code. ~1,065 automated tests.

These three repositories are private. The portfolio carries the case studies — architecture,
engineering decisions and screenshots from synthetic and fictional data only.

**How I work**

Tests are the mechanism, not the ritual — the rules this kind of software encodes cannot be
eyeballed, and a wrong answer usually looks plausible. Design decisions get written down as
architecture decision records. Privacy for student data is an architectural constraint that
the build enforces, not a policy page.
